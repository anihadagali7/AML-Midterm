`resources/` contains a compact hand-in assembled from the working Part 2 project:

- `data/`: the three supplied outcome datasets, sample submission and pathway catalog.
- `experiments/`: settings, split protocols, summary tables, figures and provenance
  for every research phase, plus row predictions used by the finalized notebooks.
  Other intermediate predictions/arrays and repeated audits stay in the working
  project and can be regenerated from the included code and supplied data.
- `src/` and `notebooks/`: preserved implementation files and historical notebooks.
- `requirements/`: pinned Python dependencies for the different workflows.
- `submissions/`: exact historical prediction CSVs and their score ledger.
- `PACKAGE_MANIFEST.json`: hashes and sizes of every included research file.

The original historical notebooks are included as research records with saved
outputs. Executing every historical notebook can require the full working checkout
or regeneration of omitted intermediate files. The three finalized notebooks run
directly from this compact package.

`results/` holds the figures and tables regenerated by these finalized notebooks.
After a clean Git checkout, run `python part2/packaging/build_handin.py` from the
repository root to materialize `resources/` and build the portable ZIP. Extracting
the ZIP provides real files and requires no Git repository, old worktree, fitted
model cache, or Part 1 checkout for these three notebooks.

## Running

Use Python 3.12 and install `resources/requirements/requirements.txt`. Open notebook
01 and run all cells. The default path recomputes metrics from saved held-out
probabilities and reconstructs the final blend from recorded native components.
For a **fresh fit from the supplied data**, set `RUN_FINAL_TRAINING=True` near the
end of notebook 01. Fresh outputs go to `generated/fresh_fit/`; the scored CSV
remains immutable. Run notebook 02 for the trial history and notebook 03 to export
and verify the embedded source copies without launching every historical search.

Only supplied outcome features train Part 2. The existing frozen Part 1 reason
table is used solely for post-hoc error analysis, with known and inferred labels
identified separately. Regenerating that table itself belongs to the separate
Part 1 workflow. See notebook 01 for the train/validation pooling and unlabeled
test-text vocabulary/IDF policy.

The initial search has 318 component-table rows and 434 ensemble-table rows;
later phases add fixed benchmark, stack/neighbor, sprint and refinement recipes.
These counts overlap controls and reuse predictions, so they are not a count of
independent trained models. Detailed results are included without requiring a
separate notebook for every configuration.
